# AI 자동 처리 보완 — 2026-10-20

초기 버전은 기본값이 `rules`여서 자유 형식 공지를 실제 AI가 분석하지 않았다. 현재는 `agent`를 기본값으로 바꾸고 이 컴퓨터에 설치된 Ollama `qwen3:8b`를 실제 실행한다. 실패 시 수동·규칙 처리로 성공을 가장하지 않는다.

## 실행 경로

`자료 등록/회원 수집 → 추출/OCR → AI 계획 → 구간별 AI 추출 → 공지 원문 대조 AI 검증 → 식품 DB 대조 → 변경안 → 근거 포함 검토 Excel`

LangGraph 상태는 run/revision/extraction/report/proposal/asset ID만 가진다. 문서 본문·OCR 좌표·분석 사실은 저장소에 보관한다. 구간별 모델 결과를 저장하고 재시도에서는 완료 구간을 건너뛴다. 원문 revision이 같고 추출 누락이 없으면 완료된 OCR을 재사용한다.

## 구현한 판단 경계

- 모델: 자료 분류, 품목/가격/규격/기간/사유/대체 후보의 의미 추출, 공지 초안의 독립 원문 대조.
- 호스트 코드: JSON 스키마, 제공한 근거 ID, 숫자/날짜 형식, 금액 인용, 단종 명시 근거, 판매 규격과 수량 일치 검증. 본문 요약과 첨부의 동일 품목·상태가 규격 상세와 중복되면 하나로 합치고 근거는 유지한다.
- DB 대조: 정규화한 이름과 규격의 정확 일치. 이름 중복은 연결 보류. 신규 제품/규격/공급 품목은 생성 변경안으로 준비한다.
- 공급처 후보·임시 날짜·단위 추정 등은 승인 전 해당 revision의 원문 대조 확인이 필요하다. 확인 사유/담당자/시각을 기록한다. 확인은 승인이 아니며, 실제 사실 반영은 기존 승인·apply 트랜잭션을 사용한다.
- 단순 일시품절을 제조 단종으로 바꾼 모델 결과는 명시적 생산 단종 근거가 없으면 자동 변경안에서 제외한다. 인용에 없는 금액은 제외한다. 검토 Excel에는 제외 이유와 원문 근거를 남긴다.
- 대체품 명칭은 추출하지만 선택/묶음/수량 관계의 복합 구성은 아직 자동 확정하지 않는다. 후보가 여럿인 식품 연결과 관계 편집 UI는 추가 작업이 필요하다.

## API와 화면

- `POST /documents/import`, `POST /price-workbooks/import`: 등록 시 자동 분석 작업 반환(`analysis_job`).
- `POST /analysis-runs`: 이미 대기/실행 중이면 동일 작업을 반환. 완료된 원문은 새 분석 run으로 재실행한다.
- `GET /analysis-runs/{id}/report`: 처리 계획, 추출 사실, DB 대조 결과, 확인 사유, 근거 ID, 실제 모델 호출 사용량, Excel asset ID.
- `POST /proposals/{id}/confirm-ai`: reviewer/admin, CSRF, 멱등 키, If-Match, 현재 revision, 확인 사유 필요. 변경 내용을 수정하면 재확인해야 한다.
- 이전 `rules` 분석 실패 작업의 재시도는 현재 `agent` 모드의 새 run으로 전환한다.
- 사이트 재수집 시 내용이 그대로인 자료도 현재 모드의 분석 이력이 없으면 AI 분석을 등록한다. 최신 AI 실행이 이미 있으면 중복 등록하지 않는다.
- 작업 상세: AI 추출 표, 원문/변경안 이동, 검토용 Excel 다운로드, 실제 모델 호출 기록.
- 표 화면: `AI로 추출·엑셀 만들기`를 기본 동작으로 제공한다. 열 직접 연결은 별도 수동 경로다.
- `/products`, `/products/{id}`, `/products/{id}/history`를 개별 Vue 경로로 등록해 빈 화면 오류를 수정했다.

## 예산·한계

로컬 AI는 CPU/GPU·메모리를 실제 사용한다. 1개 worker, 동시 분석 1개, 모델 문맥 16,384 tokens, 호출 출력 4,096 tokens, 호출 timeout 240초, 원문 창 3,000 bytes 기준, 실행당 최대 128개 창을 적용한다. UTF-8 byte 기반 입력 제한도 별도로 적용하지만 정확한 tokenizer 기반 예산 계산은 아직 없다. 초과는 명시적 실패로 남긴다. 큰 파일 전체 처리의 자동 분할·연속 실행은 후속 작업이다.

OCR 행/열 구조가 복잡한 표, 병합 셀, 낮은 해상도, 여러 가격 열과 적용 기간이 섞인 자료에는 추가 검토가 필요하다. 원문에 없는 정보를 모델이 생성할 수 있으므로 업무 DB 자동 승인·반영은 제공하지 않는다. 전체 품질/최대 RSS/처리량 벤치마크를 완료했다는 뜻이 아니다.

## 실제 검증

- `school062` 전복 인상 공지: 두 품목의 72,000원/500g, 146,000원/1kg, 2026-11-01 적용일 추출. 변경안·검토 Excel 생성. 모델 실행 기록 보존.
- `school062` 바질향 백조기순살 이미지: OCR 근거를 재사용하고 실제 AI 호출로 40~50g 규격의 2026-10-21 일시품절과 30~40g 규격의 정상 발주 가능을 구분. 최초 오분류한 초안은 superseded로 남기고 수정 실행 결과를 별도로 보관.
- 자동 테스트는 모델 테스트 대역을 명시적으로 사용한다. 실제 모델 호출을 대신했다는 주장과 구분한다. 승인 전 facts 미변경, 검토 확인 후 승인·반영·이력, 원문에 없는 금액/단종 차단, Excel 수식 실행 방지 등을 검증한다.

## 원문 대조 UX와 공통 DTO

본문/텍스트 파일, 이미지 OCR, PDF, Excel 파서는 공통 source segment(텍스트·근거 ID·원본 위치·OCR 점수)를 만든다. AI는 입력 형식에 관계없이 `food-change-dto-v1`의 식품별 DTO로 변환한다. 식품명·규격·변경 종류·금액·판매 기준 수량/단위·적용일·사유·대체 후보·근거 ID가 공통 필드다. API report의 `dto_schema`와 `version`으로 구조와 검토 동시성을 구분한다.

`/analysis-runs/{id}/review`는 품목 선택 / 원문 / 수정 폼으로 구성한다. 같은 이미지의 여러 근거는 한 이미지에 영역을 표시하고, 본문 인용과 Excel 셀 위치는 함께 보여 준다. 기존 DB 식품을 선택하면 등록 규격·현재 단가도 표시한다.

`PATCH /analysis-runs/{id}/items/{event_id}`는 version·상태(confirmed/skipped/pending)·수정 필드·사유를 받는다. reviewer/admin만 수정한다. 저장해도 업무 facts는 바뀌지 않는다. 모든 수정은 actor/시각/변경 전후를 기록하고 검토 Excel을 갱신한다. 수정하면 이전에 생성한 승인 초안을 superseded로 바꾸므로 오래된 금액을 승인할 수 없다.

`POST /analysis-runs/{id}/review-proposals`는 확인한 항목만 새 변경안으로 만든다. pending/skipped는 제외한다. 원본 AI 값과 전체 검토 스냅샷을 보관한다. 이후 기존 승인 명령과 apply 명령을 순서대로 수행한다. 승인·반영 중인 내용을 수정하는 것은 차단한다. 테스트 전용 DB에서 수정·제외·재수정 시 오래된 승인 차단·승인·반영·이력까지 검증했다.

본문/OCR 조각의 모델 입력에는 좌표를 소수 3자리로 줄이고 파일 UUID·픽셀 크기 등 추론에 불필요한 반복 메타데이터를 제외한다. 원본 근거 좌표는 바꾸지 않는다. 입력 상한으로 실패한 문서는 캐시 추출을 유지하고 새 구간 계획으로 재처리한다. 품절·공급 상태 DTO에서는 단가용 금액/기준 수량/단위를 비워 포장 수량(예: 22개)과 가격 기준 수량을 혼동하지 않는다.
