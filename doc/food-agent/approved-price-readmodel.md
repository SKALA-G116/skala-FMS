# 승인 단가가 식품 상세에 보이지 않던 문제

## 원인

식품 프로필의 `food_record.prices`는 원본 자료의 적용가·조사가·가격 열을 보관합니다. 실제 승인된 단가는 별도 `facts(kind=set_price)`에 금액·기준 수량·단위·공급처·적용 기간·근거와 함께 저장합니다.

식품 목록·상세 서랍은 프로필만 조회해 승인 단가를 보여 주지 않았습니다. 실제 눈꽃치즈 승인 건에는 29,000원/2.5kg이 저장되어 있고 단가 조회에도 나타났지만, 프로필에는 다른 조사가가 있어 승인 금액을 찾기 어려웠습니다. 최근 저장 건을 읽기 전용으로 대조해 확인했습니다.

## 변경

- `/foods`의 각 행에 `approved_prices`를 추가합니다. 원본 DTO를 덮어쓰지 않고, 같은 규격의 공급 품목에 연결된 승인 단가에서 조회합니다.
- 식품 목록과 상세 상단에 승인 금액·기준 수량/단위·적용 상태를 표시합니다. 상세에서는 공급처·적용 기간·변경 근거도 확인합니다.
- 현재 적용과 적용 예정 단가를 구분하며, 정정으로 대체된 단가와 만료 단가는 기존 기준일 조회 규칙에 따라 제외합니다.
- 식품 속성 수정 응답에도 승인 단가를 유지합니다. 속성을 저장한 직후 단가 표시가 사라지지 않습니다.
- 기존 가격 폼의 이름을 ‘원본 자료의 가격 (참고)’로 바꾸고 이 값을 수정해도 승인 단가는 변경되지 않는다고 안내합니다.

승인 단가가 없는 식품은 ‘등록된 단가 없음’으로 표시합니다. 조사가·원본 적용가를 실제 공급 단가로 자동 승격하지 않습니다. 단가 변경은 단가 변경 항목의 검수·승인 절차로 반영해야 합니다.

## 검증

- 격리 DB 통합 테스트: AI 추출 → 금액 정정 → 검수 → 승인·반영 → 식품 조회에서 최종 승인 금액과 기준 수량 확인.
- 조사가를 별도로 수정한 후에도 승인 단가가 유지되고 수정 응답·재조회에 나타나는지 확인.
- 전체 백엔드171개·프론트엔드16개 테스트와 Vite 빌드 통과.
- 실행 중인 API만 재시작한 뒤 실제 식품 목록·상세에서 29,000원/2.5kg 표시 확인. 분석 worker와 기존 승인 데이터는 변경하지 않음.
