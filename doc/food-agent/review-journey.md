# 식품 정보 검토 화면

## 사용자 흐름

1. 자료명과 검토 진행률을 확인한다.
2. 품목 카드나 전체 표에서 식품을 선택한다. 대기·확인·제외 필터와 이름·업체·규격 검색을 지원한다.
3. 원본 이미지/PDF 또는 추출 텍스트를 보며 표준 정보를 대조한다. 이미지 확대와 근거 영역 표시를 제공한다.
4. 식품명·업체·규격과 단가·적용일·사유를 먼저 확인한다. 규격 세부 정보, 식품 속성, 알레르기, 자료 가격 열은 펼쳐서 확인한다. 모르는 값은 공란으로 둔다.
5. 품목 확인/제외를 저장하면 다음 대기 품목으로 이동한다. 모두 검토하면 마지막 확인 화면으로 이동한다. 품목 확인 저장과 DB 반영은 별도다.
6. 마지막 화면에서 반영·제외·대기 건수를 확인하고 명시적으로 승인·반영한다. 승인 이후에는 편집 대신 조회와 반영 상태를 제공한다.

## 상태와 데이터 보존

- AI 추출값과 다른 값과 저장되지 않은 변경을 별도로 추적한다.
- 품목/반영 확인 화면 이동 전에 저장하지 않은 변경이 있으면 유지/취소를 선택한다. 경로 이탈과 새로고침도 경고한다.
- 알레르기 미확인은 품목 확인 여부와 별개다. 공란을 불포함으로 바꾸지 않는다.
- 구버전 검토 필드에 DTO가 없어도 보고서의 표준 DTO로 조회한다.
- 승인 API, 근거 정보, 버전 검증, 권한 검사는 기존 계약을 유지한다.

## 반응형

데스크톱은 원본과 입력 영역을 나란히 배치하고 각각 스크롤한다. 좁은 화면은 원문/정보 탭으로 전환하며 확인 버튼과 하단 탐색 메뉴가 겹치지 않도록 한다.

## 검증

- `npm --prefix frontend run build`
- `node --test frontend/tests/reviewJourney.test.js`: 상태/검색, 다음 대기 품목, 필수값/공란, 중첩 수정과 메모 감지, 구버전 DTO 조회
- 실제 완료/대기 자료에서 원문 조회, 품목 선택, 수정 유지/취소, 반영 내역 조회 확인
- 390px 화면에서 원문/정보 전환과 확인 버튼 접근 확인
- 검증 목적으로 실제 자료를 승인·반영하지 않음
