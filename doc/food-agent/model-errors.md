# 로컬 AI 요청 거절 수정

작성자: 김재현(Finn) · penguin.klg@gmail.com · 2026-10-22. 라이선스: 미지정.

## 원인

이미지 영역 계획의 `regions` 최대 40개와 각 영역의 `source_ids`·`context_ids` 최대 2000개가 중첩되어 있었다. 실제 OCR 줄은 41개였지만 Ollama의 생성 문법 변환기는 상한 조합을 반복 확장했고, llama.cpp가 `failed to parse grammar`로 HTTP 400을 반환했다. 연결 실패가 아니었는데 provider가 모든 HTTP 오류를 `MODEL_UNAVAILABLE`로 묶어 원인을 감췄다.

## 변경과 제한 유지

- 모델에 전달하는 생성용 스키마에서 배열 `maxItems`만 제거한다. 객체 구조·필수 항목·근거 ID enum은 유지한다. 원본 스키마를 변경하지 않는다.
- 응답은 **원본 JSON Schema**로 검증하므로 영역 40개, 근거 배열 상한, 중복 금지 등 기존 제약을 그대로 검사한다. 전체 OCR 줄의 포함 여부·상품 영역 중복 검사도 유지한다.
- 입력 예산·출력 토큰 상한·응답 바이트 상한·동시 실행 제한·HTTP timeout은 유지한다. 검증 실패 시 재호출이나 추측성 대체 결과를 자동 생성하지 않는다.
- HTTP 4xx 요청 거절은 `MODEL_REQUEST_REJECTED`, 404는 `MODEL_NOT_INSTALLED`, timeout은 `MODEL_TIMEOUT`, 연결 실패·서버 5xx는 `MODEL_UNAVAILABLE`로 구분한다. 모델 원문 오류 본문은 사용자 화면에 그대로 표시하지 않는다.
- 이미지 영역 계획의 입력·영역 예산 초과는 해당 자료의 모든 근거를 `manual_evidence_ids`와 도구별 `review_required`에 남기고 다음 자료로 진행한다. 예산 제한을 늘리거나 상품을 임의로 잘라 추정하지 않는다. 그 외 연결·스키마·영역 누락 오류는 계속 명시적으로 실패한다.
- worker를 정상 재시작하고 기존 재시도 경로로 실패 작업을 재개했다. 완료된 OCR·도구 결과를 재사용하며 승인된 식품 사실은 변경하지 않는다.

## 검증

2026-10-22 설치된 qwen3:8b에서 41개 근거 enum이 있는 동일 영역 스키마를 비교했다. 변경 전 요청은 HTTP 400 `Failed to initialize samplers: failed to parse grammar`, 변경 후 요청은 HTTP 200과 JSON 응답이었다. 이는 생성 문법 수락 여부 검증이며 실제 자료의 추출 정확도를 보증하지 않는다.

회귀 테스트는 동기·비동기 HTTP 400/404/503 분리, timeout·연결 오류 구분, 원본 영역 상한 초과 응답 차단, 근거 enum 유지와 원본 스키마 불변성을 검증한다.
