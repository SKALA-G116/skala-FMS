# 제품 명세

## 1. 목적과 사용자

학교급식 게시글·첨부에 흩어진 식품 정보를 근거와 함께 최신 DB로 관리한다. 사용자는 ‘무엇이 바뀌었는지, 왜 바뀌었는지, 어느 공지를 근거로 누가 승인했는지’를 확인한다.

초기 단일 조직 역할:

| 역할 | 권한 |
|---|---|
| reader | 상품·단가·이력·허용된 원문 조회 |
| reviewer | reader + 변경안 수정·승인·반려·보류·승인안 반영 요청 |
| operator | reader + 수집·분석·재처리·파일 가져오기 |
| admin | 위 권한 모두 + 공급처·소스 설정 관리 |

역할은 복수 부여 가능하다. 로그인은 우리 서비스의 로그인이다. school062 사이트 로그인은 서버측 수집기 전용으로 분리한다. MVP에서 같은 reviewer의 수정·승인을 허용하되 행위자를 기록한다. 역할 분리와 이중 승인은 확장 항목이다.

## 2. 사용자 시나리오

### A. 게시글 수집과 분석

1. 수집 화면에서 school062 소스와 게시판을 선택한다.
2. ‘새 글 확인’은 최근 목록과 설정된 재확인 범위의 기존 글을 수집한다. 이미 승인된 상품 DB는 바뀌지 않는다.
3. 작업 ID와 진행 상태가 즉시 반환된다. 창을 닫아도 작업은 계속된다.
4. 수집 목록에 제목·게시판·게시일·수집일·첨부 접근 상태·분석 상태를 표시한다.
5. 게시글 하나를 선택해 분석한다. 분석이 끝나면 독립적인 변경안 또는 서로 연관된 변경 묶음이 생성된다.
6. 첨부 로그인 필요·다운로드 실패·미지원 문서는 ‘자료 불완전’으로 표시한다. 자료의 일부만 읽었다는 점을 숨기지 않는다.

MVP 기본 수집기는 신규 자료와 최근 자료 재확인을 수행한다. 대량 과거 백필과 사이트 로그인 관리 UI는 제외한다. 초기 수집 주기는 설정 가능하게 두며 운영 허용 범위 확인 전 자동 일정을 켜지 않는다.

### B. 변경안 검토와 반영

1. 검토 작업함에서 대기·보류·충돌·실패 상태별로 검색한다.
2. 상세에서 현재 정보, 변경 예정 값, 상품 연결 후보, 적용일, 사유, 근거를 대조한다.
3. 값을 고치면 새 제안 revision이 생성된다. 원래 AI 추출 결과와 사용자의 수정 이유는 보존한다.
4. 연관 작업은 하나의 제안 안에서 원자적으로 처리한다. ‘신규 상품 등록 + 기존 상품의 대체 연결’을 일부만 반영하지 않는다.
5. 서버 검증에 통과하고 근거·대상이 확정되면 승인한다. 승인만으로 DB는 변경되지 않는다.
6. 승인 상세에 ‘반영 요청’을 제공한다. 반영 직전 대상 DB 버전과 근거 버전이 유효한지 다시 검사한다.
7. 반영 성공 시 최신 조회 데이터와 이력이 같은 트랜잭션으로 기록된다. 실패 시 일부만 반영하지 않는다.

한 가격표의 독립적인 행들은 각각 제안을 만들어 행 단위 승인할 수 있다. 연관된 변경 항목만 묶는다. 여러 제안의 일괄 승인·반영 API는 다음 단계로 미룬다.

### C. 단가표 DB 조회

제품·공급처·규격·적용일·가격 유형으로 검색한다. 기본 적용일은 한국 기준 오늘이다. 거래 조건이 다르면 별도 가격 행으로 표시한다. 같은 상품을 공급처별로 비교하되 부가세·단위·조건이 다르면 동일 조건의 최저가라고 단정하지 않는다.

각 행에서 상품 상세·가격 근거·해당 변경 이력을 연다. 조회 API는 수집·OCR·업무 데이터 반영을 발생시키지 않는다.

### D. 식품 상세와 이력

상세는 제품 → 규격 → 공급처 상품 구조다. 규격별·공급처별 현재 상태, 적용 중 가격, 미래 변경, 사유와 대체 관계를 보여준다. 이력은 기록 시각과 업무 적용 시각을 함께 표시한다. 생성도 첫 번째 이력이다.

상태를 되돌리는 작업은 과거 이력을 지우는 ‘롤백’ 버튼 대신 정정 제안을 생성한다. 정정 제안은 원래 사실·이력과 연결되고 다시 승인받는다.

| ID | 기능 | 완료 기준 |
|---|---|---|
| F01 | 소스·게시판 조회 | 세 대상 게시판과 마지막 수집 결과·접근 상태 확인 |
| F02 | 수집 작업 | 신규·수정 버전 저장, 재수집 중복 방지, 작업 재개 |

| F04 | 사건 추출 | 일시중단·종료·재개·가격·대체를 복수 사건으로 추출 |
| F05 | 상품 연결 | 코드 우선 후보 탐색, 규격 구분, 미확정 상태 보존 |
| F06 | 변경안 | 필드별 근거, 전후 값, 충돌·누락·자료 미확인 표시 |
| F07 | 검토 | 수정·승인·반려·보류, 낡은 화면의 수정 차단 |

| F09 | 단가 조회 | 적용일·공급처·단위·조건별 조회, 근거 연결 |
| F10 | 상세·이력 | 생성 포함 변경 전후·사유·승인자·원문·정정 관계 조회 |
| F11 | 대체 관계 | 원래 상품 유지, 조합·선택지·조건과 미확정 관계 표시 |
| F12 | 운영 작업 | 실패·부분 성공·재시도·취소·자료 로그인 필요 상태 구분 |

## 4. 업무 규칙

- 게시판 종류는 분류 힌트이며 상태 결정 근거 자체가 아니다. 단종 게시판에도 재개 공지가 있다.
- ‘대체식 홍보’를 특정 중단 상품의 대체 관계로 변환하지 않는다.
- 한 제품의 30~40g 규격이 정상이고 40~50g이 중단이면 후자만 변경한다.
- 공지 작성자·유통사·브랜드·제조사는 각각 다른 필드다.
- 중단 공지만 있고 기존 상품이 없으면 자동 신규 생성하지 않는다. 검토자가 식별 정보를 보완해 생성 제안을 포함시킨다.
- 같은 파일이나 교차 게시 공지의 근거는 여러 개 보관하되 같은 사건을 재반영하지 않는다. 유사도만으로 다른 공급처 사건을 병합하지 않는다.
- 본문과 첨부가 충돌하거나 첨부를 못 읽으면 범위를 명시하고 승인 차단 여부를 항목별로 판단한다.
- 사유 미기재는 unknown으로 남기며 원인을 추측하지 않는다.
- 시작일 불명확은 자동으로 게시일로 채우지 않는다. 검토자가 날짜와 판단 이유를 확정한다.
- 기간은 한국 날짜 기준 `[effective_from, effective_to)`다. 원문의 ‘종료일 포함’은 다음 날을 exclusive 종료일로 정규화한다.
- 과거 공지 도착 순서로 최신 정보를 덮어쓰지 않는다. 동일 범위·기간의 충돌은 명시적인 정정·우선순위 결정 전 반영하지 않는다.
- 제조사 단종은 제품 범위, 공급중단은 공급처 상품 범위다. 서로 다른 operation으로 분리한다.
- 대체품은 단일·조합·선택 그룹을 지원한다. 원래 상품 페이지를 자동 영구 리다이렉트하지 않는다.

## 5. 비기능 요구

- 무결성: 승인 전 변경 0건, 동일 승인 revision 중복 반영 0건, 반영·이력 부분 성공 0건을 불변조건으로 둔다.
- 추적성: 승인 항목은 근거 위치·원본 버전·파서/모델/프롬프트 버전·검토 결정으로 역추적 가능해야 한다.
- 신뢰성: 작업 상태·lease·재시도 횟수를 DB에 저장한다. 프로세스 종료 후 미완료 작업을 회수한다.
- 효율: 원본 hash와 처리 버전으로 캐시, 페이지별 처리, 모델 재사용, 제한된 OCR 동시성. 이미지 바이트를 그래프 상태나 목록 응답에 넣지 않는다.
- 보안: 역할·객체 접근 검증, 비밀은 서버측, 원문은 지시가 아닌 데이터, 허용된 사이트·파일 형식·크기·변환 시간 제한.
- 화면: 비동기 작업 상태, 빈 결과, 실패 원인, 만료된 승인, 불확실한 근거를 명시한다.
- 성능: 문서 수·파일 유형·목표 배포 환경이 미정이므로 응답 시간·월 비용 수치를 보장하지 않는다. 개발 초기에 표본 기준선을 기록한다.

## 6. v0.2 분석 기능 보강

분석 시작 시 자동/공지/단가표 프로필을 선택할 수 있다. 호스트는 프로필과 Prompt·policy·schema·parser·model 버전을 고정해 분석 run을 만든다. Resource는 원문/추출/규칙의 버전 고정 데이터이고 Tool은 최신 검색·제한된 처리 실행이다. 사람 승인과 업무 DB 반영은 모델 도구에서 제외한다.

코드 검사만으로 의미 누락을 충분히 잡을 수 없는 항목은 review_change_evidence로 검토 보조를 수행한다. 이 결과는 승인 권한을 갖지 않으며 미해결 blocker를 덮어쓸 수 없다. 예산 초과·범위 미처리는 partial/blocked/failed로 표시한다.

## 7. 제외 범위

모든 과거 글 백필, 무검토 자동 반영, 영양·알레르기 적합성 추천, 외부 발주, ERP 실시간 양방향 연동, 멀티테넌트, 벡터 검색, 자유 SQL 에이전트, 일괄 승인 API는 MVP에서 제외한다.
