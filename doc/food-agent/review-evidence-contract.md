# 다중 근거 승인 오류 수정 · 2026-10-22

상품 영역·여러 표 행을 통합한 추출 결과는20개보다 많은 evidence ID를 보존할 수 있었지만, 승인용 FieldEvidence는20개만 허용했다. 첨부 사례의22~23개 근거가 승인 과정에서 INVALID_INPUT을 발생시켰다.

OpenAPI와 food-change-v1 JSON Schema의 필드별 근거 상한을2000개로 맞췄다. 단일 OCR 결과의2000구간 처리 상한을 따르는 유한한 경계이며 UUID 형식·중복 불가·문서 소속·필드 경로·사용자 승인 검증은 유지한다. 근거를 잘라내거나 검증을 끄지 않는다.

같은 근거를 여러 필드·연산이 참조하면 한 변경안 검증 내에서는 DB에서 한 번 읽어 재사용한다. 오류 응답은 원본 값의 Python 표현을 돌려주지 않고 제한된 경로와 짧은 안내를 제공한다. 화면은 오래된 서버의 UUID 덤프도 걸러내고 중복 안내를 최대3개만 표시한다.

격리 DB에서41개 근거를 가진 품목의 확인·승인·apply와 최종 감사 이력에 모든 근거가 보존되는지 검증했다. 2000개 경계 허용·2001개 거절, 중복·잘못된 UUID 거절, 오류 응답의 원본 값 비노출을 확인했다. Backend147개·Frontend15개 및 Vite 빌드를 통과했다. 운영 식품 DB는 테스트로 승인하거나 수정하지 않았다.

첨부 오류에 해당하는 과거 검토본은 진단 시 현재 DB에서 확인되지 않아 운영 데이터 재승인은 수행하지 않았다. 기존에 저장된 확인 상태를 변경하지 않았으며, 남아 있는 검토본은 새 API에서 승인할 수 있다.
