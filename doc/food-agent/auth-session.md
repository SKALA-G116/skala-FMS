# 로그인·세션 만료 처리

작성자: 김재현(Finn) · penguin.klg@gmail.com · 2026-10-22. 라이선스: 미지정.

## 확인한 문제

쿠키 없는 사용자·식품 API는 401로 차단되고 있었다. 그러나 브라우저에서 세션이 만료되어 대시보드 API가 ‘로그인이 필요합니다’를 반환해도, Vue 메모리에 남은 관리자 정보로 메뉴와 업무 화면을 계속 표시했다. 또한 `/login`이 Dashboard 컴포넌트에 연결되어 있었다.

## 수정

- 업무 화면 이동 전에 `/auth/me`로 서버 세션을 확인한다. 인증 정보가 없으면 `/login`으로 이동하며 업무 컴포넌트를 표시하지 않는다.
- 공통 API client는 401 시 인증 상태와 CSRF 캐시를 초기화한다. 로그인 실패는 별도 오류로 표시한다.
- 창에 다시 돌아오거나 탭을 다시 볼 때도 세션을 확인한다. 서버 장애를 로그인 성공으로 처리하지 않는다.
- 로그아웃은 업무 화면을 즉시 숨기고 서버 세션을 폐기한다. 늦게 도착한 이전 인증 응답이나 로그아웃 처리 중 재확인이 인증 상태를 복원하지 못하도록 실행 버전을 검사한다.
- 로그아웃 후 로그인에는 새 CSRF 토큰을 사용한다. 로그인 제출의 중복 실행을 막고 성공 시 입력 비밀번호를 지운다.
- 새 로그인 성공 시 이 브라우저의 이전 세션을 폐기한다. 다른 브라우저의 세션 전체를 임의로 삭제하지 않는다.
- 로그인 쿠키의 8시간 Max-Age를 제거해 브라우저 세션 쿠키로 발급한다. 서버의 8시간 유효기간 검증은 유지한다. 유효한 기존 세션이 있는 같은 브라우저에서 새로고침하는 경우에는 정상적으로 로그인 상태를 복원한다. 브라우저 자체의 세션 복원 설정에 따라 세션 쿠키가 복구될 수 있으므로 ‘새 탭마다 비밀번호 재입력’ 정책과는 구별한다.
- 로그인 후 원래 업무 경로로 돌아갈 때 외부 URL·프로토콜 상대 URL·역슬래시 경로를 허용하지 않는다.

## 검증

Backend 98개, Frontend 12개 테스트와 Vite 빌드 통과. 쿠키 없음·잘못된 쿠키·만료 세션·로그아웃·재로그인 시 이전 쿠키 폐기, 익명 사용자 리다이렉트, 서버 장애, 지연 응답, CSRF 재발급을 검증했다. CI에서도 모든 Frontend 테스트를 실행하도록 갱신했다.
