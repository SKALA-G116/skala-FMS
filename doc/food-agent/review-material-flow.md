# 가져온 자료 → 검수 대기 → 표 행의 통합 정보

## 누락 원인

기존 검수함은 analysis_run.status=succeeded와 report.status=completed인 분석만 내부 결합해 조회했습니다. 그래서 새로 가져온 자료는 분석 전·대기·실패 중에는 사라졌고, 검토본을 만든 partial 분석도 누락됐습니다. 새 revision이 분석 전이면 예전 완료 결과가 현재 결과처럼 노출될 수도 있었습니다.

## 변경한 기준

검수함의 시작점은 분석 보고서가 아니라 **가져온 자료의 최신 revision**입니다. 해당 revision의 최신 run과 현재 job을 선택하고 보고서는 선택적으로 연결합니다. 작업 상태는 실제 job을 우선 사용합니다. 수집·분석을 다시 실행하거나 원본·승인 데이터를 변환할 필요 없이 기존 자료에도 적용됩니다.

| 상태 | 검수 대기 목록 | 품목 수 | 이동 |
|---|---|---|---|
| 분석 전 | 표시 | null, 화면은 분석 후 표시 | 자료 상세·분석 시작 |
| 대기/진행 | 표시 | null | 작업 진행 |
| 실패/취소 | 표시 | null | 실패 원인·재시도 |
| succeeded 또는 partial + 완료 검토본 | 표시 | 실제 추출·확인·제외 수 | 원문 대조 검수 |
| 승인·반영 중/완료 | 해당 상태 탭 | 실제 품목 수 | 검수·반영 이력 |

`status=ready`는 사용자 관점의 미반영 업무 대기 자료를 포함합니다. `review_ready`가 실제 검토본의 사용 가능 여부입니다. 분석 전0개와 분석해서0개인 경우를 구분합니다. 삭제 보관 자료는 숨기고 자료별 한 행을 유지합니다. 대기/진행 자료가 있으면 화면 목록을5초 간격으로 갱신합니다.

## 표 화면의 연결

`price-workbooks/{id}`의 `review`와 `price-sheets/{id}/rows`의 `review`가 같은 자료·revision의 검수 상태와 경로를 제공합니다. 행에는 `review_items`가 추가됩니다.

각 `review_items`는 기존 보고서의 event ID·FoodRecord DTO·검토 상태·검수 경로를 읽습니다. 검수자가 저장한 `review.fields.food_record`가 있으면 우선 표시합니다. **표 화면에 별도 DTO를 저장하거나 복제하지 않습니다.**

연결 기준은 원본 asset ID + sheet 이름 + cell 행 좌표입니다. 같은 이름만으로 상품을 추정하지 않습니다. 필터/정렬/페이지는 원본 셀 조건을 유지하고, 조회된 행에 통합 정보를 덧붙입니다. 추가된 통합 정보 자체를 검색하는 필터는 이번 범위가 아닙니다. 연결이 없는 행은 연결 없음으로 표시합니다.

표에서는 원재료·알레르기 원문 요약과 검수 링크를 같은 행에 표시하고, 행 상세에서 공통 DTO를 조회합니다. 원본 셀과 파일은 바꾸지 않습니다. 검수 수정 후 재조회하면 같은 DTO가 반영됩니다. 최종 승인 전 식품 DB가 갱신되지는 않습니다.

## 검증

Backend165개·Frontend16개와 Vite 빌드 통과. 분석 전/대기/진행/실패/부분 완료/완료의 목록 노출, 새 revision이 예전 결과를 대신 노출하지 않음, 삭제 보관 제외, partial의 검수 연결, 표·라벨 DTO 연결과 사용자 수정 재조회·원본 셀 보존을 검증했습니다.

실제 DB 읽기 전용 확인에서는 미반영 대기 자료5건과 표13행의 통합 DTO 연결을 확인했습니다. 이 중9행에 알레르기 함유 값이 있었으며, 이는 값이 존재하는 행 수로 정확도 평가가 아닙니다. 기존 식품 승인이나 수집 재실행은 수행하지 않았습니다.
