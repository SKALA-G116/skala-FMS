# 식품 정보 변경 관리 Agent — 설계 초안 v0.2

작성일: 2026-10-20 · 상태: 구현 전 계약 초안 · 기준: 현재 공유된 Python/FastAPI/LangGraph/Vue 실습 코드로 신규 설계.

## 이 초안에서 확정한 방향

- 사용자는 Vue 화면에서 수집·분석을 요청하고, 변경 전후 값과 원문을 검토한 뒤 승인·보류·반려한다.
- 조회 API는 업무 데이터를 수정하지 않는다. 분석 작업은 제안만 만들고, 승인된 제안만 별도 반영 작업이 실행한다.
- 제품, 규격, 공급처 상품을 구분한다. 공급처의 공급중단을 제품 전체의 제조사 단종으로 확대하지 않는다.
- PaddleOCR와 표 구조 분석을 사용하되 HTML·엑셀 셀은 직접 추출한다.
- 생성·수정·정정에는 원문 근거, 검토자, 변경 전후 값, 적용 시점과 기록 시점을 연결한다.
- 초기에는 단일 조직·단일 사이트·제한된 공급처와 단가표 형식·사람 승인으로 운영한다.
- API·분석 호스트·OCR/파서·승인 반영 작업자·스케줄러를 역할별 프로세스로 실행한다. PostgreSQL과 파일 저장소를 사용한다.
- 얇은 MCP 계층(6 Tool/5 Resource/3 Prompt)을 도입하고 분석 모델은 조회 Tool 3개만 사용한다.
- PostgreSQL 실행 체크포인트와 작은 참조 상태를 사용한다. 정량 검사·선택적 의미 검사·사용자 승인을 분리한다.

## 읽는 순서

1. [제품 명세](./product-spec.md): 화면과 업무 규칙, 포함·제외 범위.
2. [아키텍처와 데이터 모델](./architecture.md): 처리 책임, 데이터 관계, 중복·시간·충돌 처리.
3. [Vue 프런트엔드 명세](./frontend-spec.md): views/components, 라우트, 상태·API 연결.
4. [API 사용 안내](./api-guide.md): 승인·반영 예시, 인증·오류·페이지 규약.
5. [OpenAPI 3.1 계약](./openapi.json): 요청·응답·필터·오류 스키마. 구현된 서버의 자동 추출물이 아니다.
6. [인수 조건과 구현 순서](./acceptance.md): 기능별 완료 기준과 단계별 작업.
7. [예시 데이터](./examples/): 계약에 맞춘 가상 데이터. 실제 사이트의 DB·추출 결과가 아니다.

`validation-report.json`은 JSON 파싱, 로컬 참조·operationId·경로 변수·예시와 지원한 스키마 규칙의 검증 결과다. 전문 OpenAPI 검증기, HTTP 통합 테스트, 실제 OCR 성능 검증은 실행하지 않았다.

## 아직 합의가 필요한 사업 규칙

기준 데이터 항목은 사용자가 별도로 정해 둔 내용이 있지만 실제 항목 목록은 미제공이다. 아래 스키마는 교체 가능한 초안이다.

- 공급처 상품을 식별할 수 있는 품목코드·바코드·규격 조합.
- 가격의 부가세, 거래 단위, 공급지역·학교·계약별 적용 조건.
- 제조사 단종을 확정할 출처의 범위와 공지 충돌 시 우선순위.
- 사이트 계정과 첨부 다운로드 권한, 자동 수집·보관 범위.
- 원문·파일 보존 기간, 승인 권한과 자기 승인 허용 여부.
- 분석 표본과 목표 정확도·검토 시간·일 처리량. 숫자 목표는 실측 후 정한다.

이 항목들이 미정인 동안에는 추측 값을 운영 데이터로 반영하지 않는다. 필수 적용일·상품 연결·가격 조건이 불명확한 변경안은 차단 사유와 함께 검토한다.

## 범위 주의

이 문서 묶음은 명세·API 계약·가상 예시를 작성한 결과다. Vue 앱, 업무 DB, 로그인 서버, 수집기, PaddleOCR 실행, Git 원격 저장소 연결은 아직 구현하지 않았다. 원본 실습 코드는 변경하지 않았다.
