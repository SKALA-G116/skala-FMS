# 표 안의 이미지 라벨 분석

XLSX 셀의 텍스트와 삽입된 이미지가 서로 다른 근거로 보존되며, 같은 상품의 표준 FoodRecord DTO를 채웁니다. 표 등록은 원본 자료 등록이며 승인된 식품 DB에 곧바로 쓰지 않습니다.

## 처리 흐름

1. 셀 값을 기존 표 파서로 읽어 상품명·규격·단가를 정규화합니다.
2. XLSX drawing 관계에서 삽입 이미지와 시트·행 anchor를 읽습니다. 외부 링크는 다운로드하지 않습니다.
3. 기존 격리 OCR 프로세스에서 이미지를 하나씩 읽고 이미지 번호·행·좌표·confidence를 근거에 보관합니다. 임시 파일은 처리 후 삭제합니다.
4. Agent가 이미지 추출 도구를 선택하면 같은 시트와 행의 상품을 찾습니다. 상품 행이 정확히 하나면 이미 알려진 경계를 재분류하는 LLM 호출 없이 그 표 행과 OCR 결과를 함께 해석합니다.
5. LLM은 원재료·원산지·알레르기 등 빈 속성을 보완합니다. 표의 상품명·규격·단가를 이미지 결과로 덮어쓰지 않습니다. 알레르기는 원문의 명시적 표현을 근거로 하며 상품 사진만으로 추정하지 않습니다.
6. 기존 통합 단계에서 표 후보와 라벨 후보를 한 검토 품목으로 합칩니다. 필드 출처와 표·이미지 근거를 유지합니다. 검수 화면에서 원본 라벨과 OCR 텍스트를 비교하고 승인한 뒤 DB에 반영합니다.

여러 상품 행에 걸친 anchor는 자동으로 한 상품에 연결하지 않습니다. Agent 로그와 검수 대상에 남깁니다. 표 행이 없는 이미지 전용 시트는 기존 상품 영역 추출 도구를 사용합니다.

## 범위와 자원 제한

- 파일 업로드·사이트 첨부·분석 입력 상한은 **25MiB(26,214,400 bytes)**입니다. UI에서는 25MB로 안내합니다. multipart 전체 요청에는 별도 1MiB 여유가 있습니다.
- 현재 추가 지원은 **XLSX 삽입 PNG·JPEG·WEBP·GIF**입니다. 구형 XLS의 그림, 연결 이미지, SVG·WMF는 이 기능의 지원 범위가 아닙니다.
- 이미지 목록은 최대 2,000개, OCR 자동 분석은 파일당 앞의 40개까지입니다. 초과 이미지가 있어도 표 행은 유지하고 미처리 수를 표시합니다.
- ZIP 해제 크기 100MiB, 이미지당 1,600만 픽셀, 기존 분석 구간 2,000개 등은 별도 제한입니다. 25MB 파일이라고 모든 내용을 무제한 분석하는 것은 아닙니다.
- 이미지를 원본 XLSX asset 안에 보관하고 필요할 때 추출하므로 별도 중복 이미지 파일은 저장하지 않습니다. 미리보기는 기존 인증·서명·원본 asset 권한을 검사합니다.
- OCR 비활성화·인식 실패·모호한 연결은 검수 대상으로 남습니다. 텍스트가 있는 PDF 내부의 그림을 별도로 추출하는 기능까지 추가된 것은 아닙니다.
- parser 버전은 food-parser-v7입니다. 기존 완료 결과를 자동 변경하지 않으며, 새 분석에서 적용합니다.

## 검증과 한계

합성 XLSX와 모의 OCR/모델로 두 이미지의 행 구분, 표 값 유지, 원재료·알레르기 보완, 중복 품목 통합, 원본 미리보기 권한, OCR 미설정, 40개 초과 시 표 보존을 검증했습니다. 실제 업로드·사이트 첨부의 25MiB와 1 byte 초과 경계도 테스트합니다.

사용자가 제공한 단가표 화면 캡처의 라벨을 실제 OCR·LLM으로 정확하게 읽었다는 의미는 아닙니다. 해당 파일 원본을 새로 분석하여 검수해야 합니다. 작은 라벨은 원본 이미지 해상도·압축 정도에 따라 읽히지 않을 수 있습니다. 표와 라벨이 상충하는 경우에는 검수자가 원문을 기준으로 확인해야 합니다.
