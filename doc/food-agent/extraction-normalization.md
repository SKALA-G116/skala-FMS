# 표 추출 누락 진단과 수정

2026-10-21 확인한 분석 `4c00830b-0acb-49ec-bcf1-03a8c50dff2d`는 표를 읽었지만, DTO 속성 분리 규칙이 원유·대두·밀·쌀 일부만 인식했다. 원본이 사라진 문제가 아니라 후속 정규화와 검토 UI에서 정보가 충분히 전달되지 않은 문제였다.

## 변경한 흐름

원본 표 읽기 → 열 이름 매핑 → 공통 DTO 정규화 → 중복 근거 통합 → 원문 대조·수정 → 사용자 확인 → 승인·DB 반영.

- 원재료명을 특정 목록으로 제한하지 않고 명시된 함량(%)을 분리한다. 괄호 안 쉼표는 원재료 구분자로 취급하지 않는다.
- `국산생멸치75%,천일염25%,2년숙성` → 생멸치 75%(원재료 원산지 KR), 천일염 25%, 기타 속성 `2년숙성`. 제품 전체의 원산지를 국산으로 추정하지 않는다.
- 규격·판매 단위를 기타 속성에 중복 표시하지 않으며 원문은 그대로 보존한다. Excel의 `_x000D_` 헤더 인코딩을 제거하고 환산 규격 열도 읽는다.
- 속성 원문·원재료·함량·숙성 등 기타 속성과 비고를 검토 화면에서 표시하고 수정할 수 있다. 원재료가 있다는 사실만으로 알레르기 함유 표시를 확정하지 않는다.
- 비고 `바다천지`는 업체라고 단정할 수 없으므로 비고에 보관하고 검토자에게 보여준다. 조사 가격을 공급 단가로 자동 승격하지 않는다. 공란과 0원을 구별한다.
- 작업 화면은 내부 proposal 묶음마다 버튼을 생성하지 않는다. 식품 정보 검토 진입점 하나와 원본·Excel 다운로드를 제공한다. 전체 행은 검토 화면에서 보고 작업 화면은 미리보기 5개만 렌더링한다.

## 기존 결과 복구

`POST /api/v1/analysis-runs/{id}/normalize` (admin/reviewer, CSRF와 Idempotency-Key 필요).

저장된 extraction을 최신 정규화 규칙으로 다시 읽는다. 새 검토 초안과 Excel을 만들며 기존 분석·검토 결정·승인 DB는 변경하지 않는다. 같은 보고서 버전·정규화 버전에는 같은 결과를 반환한다. 새 초안에서는 사용자 확인을 다시 받아야 한다. 완료 전 분석과 삭제된 자료에는 적용할 수 없다. 화면의 **원본 표로 다시 정리** 버튼으로 실행한다.

최신 Agent 분석에서는 경량 모델이 도구를 결정한 뒤, 구조화된 표의 행마다 추가 LLM 호출을 하지 않는다. 원본 표 재정리에는 판단이 끝난 표 자료를 재사용하므로 새 LLM 호출이 없다. LLM은 비정형 텍스트·OCR 의미 해석을 맡고, 명확한 표의 열과 수치는 파서가 처리한다. 이번 수정은 이미지 표의 공간 배치 복원이나 전체 OCR 정확도 향상을 검증한 결과가 아니다.

## 검증

- 실제 저장된 원본 520개 구간의 검토 품목 259개를 유지하며, 간장 항목의 누락된 원재료와 숙성 속성을 복구했다. 미리보기는 DB를 변경하지 않는다.
- 원재료 국산 표시는 제품 원산지에 전파하지 않음, 알레르기 미확정 유지, 0원/조사가 구별, 캐시 재정규화 후 행·시트·근거·원문 버전 추적 보존을 회귀 테스트했다.
- 기존 검토 기록을 보존하는 새 검토본 생성과 동일 요청 재사용을 API 통합 테스트했다.
- Backend 97개, Frontend 검토 동선 5개 테스트 통과. Frontend 빌드 통과.

## 남은 한계

업체가 비고에만 있는 경우 자동 확정하지 않는다. 함량 없는 복잡한 혼합 원재료·가변 서술·이미지 표의 공간 관계는 별도의 추출 품질 검증이 필요하다. 이 수정으로 모든 게시글과 이미지의 정확도가 해결되었다고 판단할 수 없다.
