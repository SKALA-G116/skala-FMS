# 운영 흐름 보완 — 2026-10-20

## 사용자 흐름

1. **사이트 연결·수집**에서 기존 school062.com 회원 정보를 입력하고 연결 확인.
2. 지금 업데이트 가져오기 또는 자동 수집 간격 설정. 처음에는 선택 범위만 수집하고 이후 새 글·최근 수집 글의 수정을 확인.
3. **자료 관리**에서 본문·첨부·추출 결과를 확인. 제목 행은 앞 20행의 열 이름 패턴으로 제안하고 사용자가 수정할 수 있다. XLSX는 ‘표 검토’ 또는 ‘가져온 표 모아보기’로 이동.
4. 표의 식품명·규격·판매 단위·가격 열, 실제 공급처, 적용일·세금 기준을 명시해 단가 변경안 준비. 기본값으로 가격 열이나 공급처를 추측하지 않음.
5. **변경안 검토**에서 원문과 작업 묶음을 확인하고 승인 후 DB 반영.
6. **단가표 조회**는 반영된 DB 가격 하나의 화면으로 제공. 원본 자료와 승인 단가를 조회 탭으로 섞지 않음.

## 실제 구현

- GNUboard 공개 로그인 폼에 맞춘 인증과 자동 로그인 쿠키 재사용. 만료 시 저장한 계정으로 재인증. 성공은 로그아웃 링크를 통한 회원 상태로 검증.
- 비밀번호·세션 쿠키는 Fernet 암호화. 키는 DB와 분리된 권한 0600 파일 또는 FOOD_CREDENTIAL_KEY. 계정 API는 admin만 접근하고 비밀번호·쿠키를 반환하지 않음. 키와 DB를 함께 백업해야 복원 가능.
- source+board+post ID 기준 고유성. 제목·본문·첨부 내용 해시·접근 문제로 변경 감지. 기존 document ID와 최초 수집일은 유지하고 불변 revision 추가. 단순 조회수 변경은 해시에 넣지 않음.
- 게시판별 마지막 확인 ID·이어 읽을 페이지 저장. 최초 수집은 지정 범위에 한정. 이후 새 글과 최근 14일 내 수집 자료를 오래 확인하지 않은 순서로 다시 방문. 게시판당 실행 범위 외 신규 backlog는 다음 실행에서 이어 확인.
- 게시글 단위 짧은 트랜잭션으로 저장. 외부 HTTP 동안 DB 트랜잭션을 열지 않음. 하나의 첨부에 접근하지 못해도 본문과 다른 첨부를 보관하고 부분 완료 표시.
- 같은 출처의 활성 수집 요청은 기존 job을 재사용. worker의 30초 scheduler tick이 설정 간격마다 durable 수집 job 등록. 로그인 실패 상태이면 자동 실행을 대기시켜 반복 로그인 실패 방지.
- 허용 HTTPS 호스트·포트·리다이렉트 검사. 파일당 25MiB, 게시글 첨부 20개/합계 60MiB. 로그인 HTML을 Excel로 잘못 저장하지 않음.
- 새/수정 자료는 자동 분석 job으로 연결. 판단 불가한 규칙 분석은 ‘원문 추출 완료·검토 필요’로 표시하고 수동 검토로 연결. 성공한 판단처럼 표시하지 않음.
- 모든 첨부를 순서대로 추출. 일부 첨부 추출 실패는 기록하고 승인 차단. 한국어 PaddleOCR 3.7 + PaddlePaddle 3.3.1을 별도 Python 3.11 환경에 설치. PP-OCRv5 mobile detection + korean_PP-OCRv5_mobile_rec 명시. 이미지와 스캔 PDF 페이지 OCR, 120초 task timeout.
- 실제 공개 공지 이미지에서 한국어 텍스트 17구간 추출 확인. 원본 이미지와 정규화 좌표를 연결하며 UI에서 해당 영역 강조 표시. PDF는 페이지를 지정한 원본 미리보기.
- 표에서 여러 행을 식품별 처리 후 최대 50 operation의 승인 묶음으로 나눔. 정확히 일치하는 이름/규격/공급처/판매 단위만 기존 품목으로 연결. 모호한 중복과 잘못된 단위/금액은 제외 사유 표시. 0원은 기본 제외하고 명시적으로 선택 가능. 공통식품코드를 공급처 품목코드로 오해하지 않도록 자동 매핑하지 않음.
- 기존 가격 정정은 담당자가 명시적으로 선택. 해당 조건에 겹친 사실이 하나일 때만 supersedes_fact_id 연결. 여러 이력이 얽힌 경우 별도 검토.

## 실행과 검증의 경계

실제 공개 게시글 4건에서 본문·이미지·권한 제한 첨부 구분을 확인했다. 사용자가 설정한 실제 회원 연결 성공을 확인했고, 이후 수집 45건(신규 36·수정 6·동일 3)에서 Excel 첨부를 받았다. 첨부 개수 상한 초과 1건은 부분 완료로 남겼다. 25개 표를 검토 목록에 연결했고 1개는 별도 확인이 필요하다. 추가 인증·캡차·권한 제한을 우회하지 않는다.

자유 형식 게시글의 완전자동 의미 분석은 여전히 설정한 모델 API가 필요하다. 현재 모델 미설정 시 추출 후 수동 검토를 제공한다. OCR 1장 실행은 검증했지만 식품 자료 전체의 정확도 보증·RSS/지연 부하 인증은 아니다. OCR 프로세스는 작업 후 종료하므로 메모리는 회수하지만 매번 모델 초기화 비용이 있다. 전용 프로세스 풀 모델 재사용과 운영 환경 자원 상한은 후속 개선이다.

HWP 등 현재 지원하지 않는 첨부는 원본을 보관하고 추출 불가를 표시한다. 원본 파일의 값이 자동으로 ‘승인된 가격’이 되는 경로는 없다. Docker 설정은 제공하지만 이번 검증은 로컬 PostgreSQL/Python/Vue 환경에서 수행했다.

설계상의 모든 운영 과제(전체 응답 DTO 계약 인증, 장기간 백업·보존 GC, 장애 부하 실험 등)가 완료됐다는 뜻은 아니다.

최종 회귀 테스트 27개 및 Vue 프로덕션 빌드 통과. 실제 표의 첫 행이 아닌 제목 행 인식과 가격 기준 지정 화면도 브라우저에서 확인했다.
