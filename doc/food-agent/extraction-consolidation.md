# 업체 표 정규화와 검토 후보 통합

상품 안내 이미지와 첨부 표에 같은 품목이 반복될 때, 이미지의 문장·규격·가격을 각각 사용자 검토 행으로 만들던 문제를 개선했습니다.

## 처리 순서

1. 원문 텍스트·OCR와 셀/페이지 좌표는 그대로 보존합니다.
2. 상품명·규격·단위·학교가·원재료 등 열 이름을 인식하면 코드로 표준 DTO에 직접 연결합니다. 빈 서식 행은 모델 입력에서 제외합니다. 인식할 수 없는 본문·이미지는 LLM 처리를 유지합니다.
3. `㈜`, `(주)`, `주식회사`의 표시 차이는 업체명을 비교할 때 정규화하고 원문은 필드 근거에 남깁니다. 특정 서식의 회사명 한 줄은 같은 시트의 다음 표에서만 사용하며 타 파일로 전파하지 않습니다.
4. 학교가·납품가 같은 명시적 공급 가격 열은 품목 정보와 하나의 가격 후보를 구성합니다. 적용가·조사가는 기존 정책대로 별도 원본 가격 속성입니다. 적용일은 원문에 없으면 공란입니다.
5. 동일한 업체·식품·규격·가격·기간 후보는 통합하고 모든 근거 ID와 원래 후보 ID를 연결합니다. 이름 일부가 생략된 OCR은 대응하는 표 품목이 하나인 경우에만 연결합니다.
6. 업체·식품코드·맛·규격·가격·조건·기간이 충돌하거나 대응 후보가 여럿이면 분리합니다. 근거 없는 가격 후보는 이력에 보관하고 빈 가격 검토 행으로 반복하지 않습니다.
7. 사용자가 검토하기 전에는 DB 식품·단가 사실을 확정하지 않습니다.

## 알레르기·원산지

원재료의 계란·우유는 알레르기 **후보**입니다. 표시사항을 확인하지 않고 함유 확정으로 바꾸지 않습니다. 계란(국산)은 해당 원재료의 원산지이며 식품 전체의 원산지로 복사하지 않습니다. 원재료 원문·함량·출처는 함께 보존합니다.

## 이미 끝난 분석 정리

```sh
.venv/bin/python scripts/reconcile-extraction.py --run-id RUN_ID --dry-run
.venv/bin/python scripts/reconcile-extraction.py --run-id RUN_ID --actor admin
```

저장된 텍스트·OCR와 원문 표를 다시 연결하므로 OCR/LLM 추가 호출이 없습니다. 새 분석 ID·검토 결과·Excel·완료 작업 기록을 생성하며 모든 항목은 다시 검토 대기입니다. 이전의 수정·제외·확인·승인 기록과 DB 사실은 덮어쓰지 않습니다. 동일 원본 보고서 버전·통합 버전으로 반복 실행하면 같은 정리 결과를 반환합니다. 이 도구는 전체 AI 분석을 재실행하는 도구와 구분됩니다.

## 검증과 한계

테스트는 실제 업체명 대신 작은 공급 표를 만들어 열 매핑·가격 0/공란·원재료·후보 알레르기·출처·모호한 규격·다른 업체/가격/기간의 분리·이전 검토 보존·반복 정리의 중복 방지를 검사합니다. 인식 가능한 열 이름을 확장한 것으로 모든 공급업체 양식을 해석한다고 보장하지 않습니다. 알레르기 표시와 적용 시작일은 계속 사용자 확인 대상입니다. 통합 단계 자체는 결정적 로직이며 새 LLM 호출이 없습니다. 전체 Agent의 추론 속도 개선률을 의미하지 않습니다.
