# 원재료 속성 누락 원인과 수정

원재료의 표준 저장 위치는 `FoodRecord.attributes.ingredients`입니다. 각 항목에 이름·함량·원산지·원문을 보관하며, 함량이 없으면 null입니다. 검수 화면과 승인된 식품 프로필은 이 DTO를 사용합니다.

## 확인한 원인

- 일반 속성 원문을 정규화할 때 `%`가 있는 토큰만 원재료로 분류했습니다. 실제 저장된 만두 분석에서 함량 없는 대두유·부추·마늘 등이 `attributes.other`에 남았습니다.
- LLM 응답에는 원재료 전용 원문 필드가 없고 포괄적인 `attributes_text`만 있었습니다. 맘스케익 저장 결과에서는 이 필드에 제품명·내용량·제조원 설명이 남고 원재료 목록은 빠져 있었습니다. DTO 누락과 앞단 추출 누락은 별개의 문제입니다.
- 원재료 원산지 판정이 `미국산`의 `국산` 부분까지 일치시켜 KR로 잘못 분류했습니다.

## 변경한 처리 계약

1. 텍스트·라벨 응답에 선택 필드 `ingredients_text`를 추가합니다. 기존 응답도 허용하고 기존 DTO의 저장 위치는 유지합니다.
2. 전용 원재료 원문은 함량 유무와 관계없이 구조화합니다. 괄호 안의 복합 원재료는 한 항목으로 유지합니다.
3. `원재료명 및 함량`처럼 명시된 원문 구간은 다음 표시사항 제목 전까지 읽습니다. 보관방법·영양정보·알레르기 문구를 원재료 목록에 섞지 않습니다.
4. LLM이 반환한 원재료 원문도 기존 근거 검사를 적용합니다. 같은 엑셀 행에 명확하게 연결된 라벨에서 전용 응답이 누락되면 명시된 원재료 구간만 OCR 원문에서 복구합니다. 추론 호출은 추가하지 않습니다.
5. 통합 DTO의 원재료에 이미지 근거를 연결합니다. 미국산을 국내산으로 해석하지 않으며, 확인하지 않은 국가 코드는 공란으로 둡니다.

## 검증과 적용 범위

함량 없는 원재료·함량/미함량 혼합·외국산·보관정보 구분을 단위 테스트로 검증합니다. 합성 XLSX와 모의 OCR/LLM 통합 테스트에서는 같은 행의 원재료 DTO 보완, 원문에 없는 응답 배제와 원문 구간 복구를 확인합니다. 이는 실제 라벨 OCR 정확도 측정이 아닙니다.

기존 저장 분석과 승인된 식품은 자동 덮어쓰지 않습니다. 이 변경은 이후 분석에서 적용됩니다. 과거 자료는 재분석 후 원문을 대조하고 승인해야 합니다. OCR가 읽지 못한 글자는 이번 수정만으로 복원되지 않습니다.

수정 후 격리 DB·규칙 모드와 모의 LLM/OCR을 사용하는 전체 백엔드 테스트 **171개 통과**(2026-10-22). 기존 실제 분석의 원재료를 자동 복구하거나 재승인한 결과는 아닙니다.
