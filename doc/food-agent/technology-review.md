# 기술 적절성·변경 결정 기록 — v0.2

2026-10-20. PDF 7~8쪽의 ADR 방식(배경·결정·대안·결과·재검토 조건)을 적용했다. 교육 자료에서 채택한 기술과 실제 서비스에서 필수인 기술을 구분한다.

## ADR-001 — 제한된 MCP 도입

- 배경: v0.1은 내부 라이브러리 직접 연결과 MCP 생략을 허용했다. 이번 요청은 PDF 기반의 capability 계약과 일관된 도구 연결을 요구한다.
- 결정: FastMCP stdio server 1개/분석 호스트. 동적 검색·파싱 작업·검증·제안 저장의 6종 Tool, 버전 고정 5종 Resource, 표준 절차 3종 Prompt를 명세한다. 모델은 조회 Tool 3개만 본다.
- 대안: 직접 함수만 사용하면 프로세스·프로토콜 비용이 적다. 원격 MCP는 독립 확장이 쉽지만 인증·네트워크 운영이 늘어난다.
- 결과: 초기 구조가 조금 복잡해진다. 대신 capability 발견·입출력 계약·Inspector 독립 시험이 가능하다. 공통 유스케이스를 REST/MCP가 재사용해 로직 중복을 막는다. MCP 사용 자체가 메모리 절약이나 오류 격리를 보장하지 않으므로 수명·자식 회수·상한이 필요하다.
- 재검토: 호스트 수 증가로 subprocess·DB 연결 중복 비용이 커지면 공유 원격 MCP 또는 일부 직접 연결을 다시 비교한다. 원격화 시 최신 지원 transport와 인증을 검증한다.

## ADR-002 — PostgreSQL 실행 체크포인트 채택

- 배경: 원문 파일과 다단계 OCR/LLM 처리는 재시작 후 같은 실행을 복구할 필요가 있다. v0.1의 job/cached artifacts만으로는 그래프 cursor 복구 계약이 부족했다.
- 결정: 배포용 분석 그래프에 AsyncPostgresSaver와 생성 factory를 사용한다. run/thread·입력·처리 버전을 고정한다. MemorySaver는 단위 시험용으로만 허용한다.
- 대안: 처음부터 모든 단계 재실행은 단순하지만 모델 호출과 처리량을 낭비한다. SQLite는 단일 개발 환경에는 쓸 수 있지만 다중 작업자와 중앙 실행 기록을 위해 별도 운영 조합을 만들 이유가 적다.
- 결과: checkpoint 저장·직렬화·보존 비용이 생긴다. state를 작은 참조로 제한하고 완료 실행을 정리한다. 비즈니스 DB가 업무 사실·승인·반영의 권위 저장소이며 checkpoint가 이를 덮어쓰지 않는다.
- 재검토: 전체 문서가 짧고 재실행 비용이 무시 가능하다고 실측되면 일부 경량 파이프라인에서 체크포인트 생략을 재평가한다.
- 근거: PDF 22, 209~213, 220쪽; [LangGraph 영속 메모리](https://docs.langchain.com/oss/python/langgraph/add-memory).

## ADR-003 — PaddleOCR 유지, OCR 작업자 분리

- 배경: 한국어 이미지의 규격별 상태와 표 연결이 중요하다. 외부 OCR 대비 정확도·자원 실측은 아직 없다.
- 결정: PaddleOCR 한국어 인식과 표 구조 파이프라인을 1차 후보로 유지한다. HTML·XLS/XLSX는 직접 추출한다. OCR 모델은 별도 작업자 한 개에서 재사용하며 MCP/API에 로딩하지 않는다.
- 대안: 관리형 OCR은 도입·운영을 줄이지만 호출 비용·외부 전송이 있다. VLM만으로 모든 표를 구조화하면 원문 좌표·수치·누락의 검증이 더 필요하다.
- 결과: CPU/GPU·라이브러리 호환성·모델 메모리 운영 책임이 남는다. PP-OCR 인식기와 PP-Structure의 detector/recognizer를 중복 로딩하지 않는 실제 pipeline 구성을 확인한다. 초기 1 worker는 정책 시작값이며 성능 보장이 아니다.
- 재검토: 실제 표본에서 금액·규격·행 연결 오류나 검토 시간이 목표를 넘으면 전처리·모델 설정을 조정하고 실패 문서 유형에 한해 다른 OCR을 비교한다.
- 호환성: Python/PaddlePaddle/PaddleOCR/표 모델/CPU·GPU runtime을 실제 환경에서 검증하고 버전·모델 hash를 고정한다. 최신 버전이라는 이유만으로 교체하지 않는다.

## ADR-004 — 정량 검사 + 선택적 의미 검사 + 사람 승인

- 배경: 기존 실습의 글자 수/번호 검사로는 상품·단위·시점·근거 누락을 검증할 수 없다. PDF 18쪽·165~169쪽은 LLM Judge를 설명한다.
- 결정: Pydantic + 업무 코드 검사 + 필요 시 의미 검토 Prompt를 사용한다. 사용자 승인 전 실제 DB 반영을 금지한다. 의미 검토는 누락·모순 지적만 하고 최종 사실 판정·권한 검사를 대체하지 않는다.
- 대안: 규칙만으로 의미 오류를 전부 잡기 어렵고, 모든 행에 Judge를 쓰면 비용·지연과 비결정성이 늘어난다. Judge 합격만으로 DB 반영하면 수치 오류를 통과시킬 수 있다.
- 결과: 자동화율보다 검토 가능한 근거와 무결성을 우선한다. 재검토 상한 후에도 미해결 항목은 차단한다.
- 재검토: 충분한 검수 데이터와 업무 위험별 성능이 확보되면 좁은 저위험 변경부터 자동 승인 정책을 별도 ADR로 결정한다.

## ADR-005 — PostgreSQL 작업 큐와 조회 polling 유지

- 배경: PDF는 실시간 답변 토큰 전송에 SSE를 채택하지만 이번 UI는 지속 작업의 상태·확정 결과가 중심이다.
- 결정: DB lease 작업 큐, 조회 polling, 같은 origin REST를 유지한다. SSE는 후속 UX 개선이다. OCR 대기를 웹 요청/브라우저 수명에 묶지 않는다.
- 대안: Redis/Celery는 복잡한 큐·스케줄 운영에 장점이 있지만 초기 운영 요소를 늘린다. WebSocket은 현재 양방향 스트림 요구가 없다.
- 결과: polling 빈도·backoff와 작업 조회 인덱스가 필요하다. lease/fencing·재시도·timeout을 직접 구현해야 하므로 DB 작업 큐가 ‘무료’인 것은 아니다.
- 재검토: 대기열 지연·분산 worker 수·큐 운영 요구가 커지면 전문 큐를 도입한다. 실시간 상태 UX가 필요하면 기존 job 상태를 권위로 둔 SSE를 추가한다.

## ADR-006 — 자유 CRUD/물리 삭제/벡터 메모리/자율 Agent 확장 보류

- 배경: 핵심 데이터는 정확한 제품 식별·적용 시점·변경 이력이다. SQL을 모델이 자유 생성하거나 유사도만으로 결론내면 무결성을 잃는다.
- 결정: 승인된 7종 operation만 committer가 실행한다. 단종은 상태 변경, 정정은 새 사실, 원문 근거는 불변 참조다. RAG·벡터 DB·여러 독립 Agent는 필수 기능으로 넣지 않는다.
- 대안: 자유 SQL은 유연하지만 권한·범위·검증을 어렵게 한다. 벡터 검색은 후보 탐색에 도움이 될 수 있으나 식별자·단위·원자적 반영을 대신하지 못한다.
- 결과: 역할 분리 노드는 유지하지만 모든 기능을 독립 Agent로 만들지 않는다. 문서·계약·테스트 가능한 도구의 수를 작게 유지한다.
- 재검토: 이름·별칭 검색의 정량 평가에서 명확한 실패가 확인되면 의미 검색을 후보 생성에만 도입한다. 물리 삭제는 보존·참조·권한 정책이 먼저다.
