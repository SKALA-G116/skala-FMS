# 과정과 결과 중심 5분 발표 진행안

[README](../../README.md)1~7절을 순서대로 보여 줍니다. 본문은 청중에게 공유하고, 아래 발화 예시는 발표자만 참고합니다. 시간표는 화면 전환을 포함한 배분안이며 실제 리허설 측정값은 아닙니다. README의 ‘결과 보고서 · 개발 및 검증 상세’는 제출·질의응답용으로 접어 두고7절 기대효과로 이동합니다.

| 시간 | 화면 | 전달할 내용 |
|---|---|---|
| 0:00~0:40 | 1절 | 자료가 흩어져 있어 반복 확인이 필요함 |
| 0:40~1:15 | 2절 | 빵 단가표·라벨·중단 공지라는 쉬운 예시 |
| 1:15~1:55 | 3절 | Agent의 도구 선택과 사람의 승인 |
| 1:55~3:45 | 4절 · 화면3장 | 자료 확인→원문 검수→승인 단가 조회 |
| 3:45~4:15 | 5절 | 정보가 섞이거나 보이지 않던 문제를 개선 |

| 4:35~5:00 | 7절 | 기대효과와 앞으로의 검증 |
| 합계 | **300초** | 코드와 설치 명령은 열지 않음 |

## 배경 · 40초

“학교에서 식단을 준비할 때는 가격뿐 아니라 지금도 주문할 수 있는 제품인지 확인해야 합니다. 그런데 가격은 엑셀, 중단 안내는 게시글, 원재료는 이미지에 흩어져 있습니다. 광주 초·중·고는 공개자료 기준314개교입니다. 학교마다 같은 공지를 읽고 옮긴다면 반복되는 업무입니다. 이 자료 정리를 돕기 위해 식품장부를 만들었습니다.”

학교 수는2025-11-09 기준 자료 설명이며 실제 이용 학교 수가 아닙니다. 숫자 내역과 출처는 README에 두고 모두 읽지는 않습니다.

## 쉬운 사례 · 35초

“빵 단가표와 라벨을 받았다고 생각해 보겠습니다. 표에서는 이름과 규격·가격을 정리하고, 라벨에서는 원재료와 알레르기를 읽어 같은 제품에 연결합니다. 공급 중단 공지가 있으면 상태 변경을 검토할 초안으로 만듭니다. 담당자는 원문을 보고 수정하거나 제외한 뒤 승인합니다.”

가상 예시를 실제 실행 기록으로 소개하지 않습니다. 대체품 관계는 별도 관계 검토가 필요한 범위도 있으므로 자동 확정 기능으로 설명하지 않습니다.

## 처리 과정 · 40초

“Agent의 역할은 자료를 보고 어떤 도구로 처리할지 고르는 것입니다. 표는 표 정리 도구로, 문장은 텍스트 해석으로, 이미지는 글자를 읽은 뒤 상품별 정보 추출로 보냅니다. 부족한 자료는 사람이 확인하도록 남깁니다. LangGraph는 이 작업의 순서와 중간 저장을 관리합니다. 마지막 승인은 사람이 하고, 승인 전에는 확정된 식품 정보를 바꾸지 않습니다.”

다이어그램만 따라 설명합니다. 함수 이름·좌표 배열·모델 설정은 설명하지 않습니다.

## 실제 화면 · 110초

| 시간 | 행동과 설명 |
|---|---|
| 1:55~2:20 | 자료 목록: “가져온 자료와 분석 진행 상태를 한곳에서 확인합니다. 준비가 되면 검수로 이동합니다.” |
| 2:20~3:10 | 라벨 검수: “왼쪽 원문과 오른쪽 정보를 비교합니다. 잘못 읽은 값은 수정하고 불필요한 항목은 제외합니다. AI가 틀릴 수 있어 확인 과정이 필요합니다.” |
| 3:10~3:45 | 승인 단가: “별도로 승인돼 있던 치즈 사례입니다.29,000원/2.5kg과 적용일, 변경 근거를 상세에서 확인할 수 있습니다.” |

세 화면은 서로 다른 저장 자료의 조회 기록입니다. 앞의 빵을 승인해 뒤의 치즈가 생성됐다고 설명하지 않습니다. 최신 OCR 수정 후 새 추론을 시연한 결과도 아닙니다. 시간 안에 새 분석을 기다리거나 운영 자료를 시연용으로 승인하지 않습니다. [선택적 라이브 시연 준비](demo-guide.md)

## 개선 경험 · 30초

“처음에는 이름과 무게가 같으면 다른 맛까지 합쳐지는 문제가 있었습니다. 딸기맛50g과 초코맛50g은 다른 항목이므로 통합 기준을 바꿨습니다. 이미지의 위치와 근거를 유지하고, 승인 단가도 상세 상단에 보여 주도록 했습니다. 읽은 정보를 올바른 상품에 연결하고 확인할 수 있어야 한다는 점이 중요했습니다.”

맛 예시는 개선 원리 설명용입니다. 위치·근거 개선은 회귀 테스트로 확인했으며 실제 정확도 상승률을 측정한 결과로 소개하지 않습니다. 수치·기술을 질문받으면 [Before/After](before-after.md)와 [OCR 검증](../food-agent/ocr-spatial-evidence.md)을 엽니다.

## 앞으로 개선할 부분 · 20초

“앞으로는 작은 라벨을 필요한 부분만 다시 읽어 정확도를 높이고, 같은 자료를 반복 처리하는 시간을 줄이고 싶습니다. 실제 담당자가 사용하면서 얼마나 수정하고 얼마나 오래 검토하는지도 측정해 개선하려 합니다.”

확대 재OCR는 향후 목표입니다. 현재 이미 완료한 기능으로 소개하지 않습니다.

## 기대효과 · 25초

“기대하는 효과는 세 가지입니다. 흩어진 자료를 찾아 옮기는 부담을 줄이고, 가격이나 공급 변경을 장부와 근거로 함께 확인하며, 변경 이력으로 인수인계를 돕는 것입니다. 작은 라벨의 정확도는 더 개선해야 합니다. 앞으로 실제 담당자의 검토 시간과 수정 횟수를 측정해 효과를 검증하려 합니다.”

발표 전 화면3장과 Mermaid 표시를 확인하고300초 타이머로 리허설합니다. Zoom 공유와 확대율은 발표자가 확인합니다. 기대효과를 이미 실측한 성과로 소개하지 않습니다.
