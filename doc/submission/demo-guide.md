# 발표 환경과 시연 준비

## 기본 발표 방식: README와 저장된 결과 공유

[README](../../README.md) 4절의 캡처를 **105초** 동안 순서대로 보여 줍니다. 새 추론을 기다리거나 운영 자료를 승인할 필요가 없습니다. 전체300초 배분과 발화 예시는 [발표 흐름](presentation-5min.md)을 따릅니다.

|---|---|---|
| ①20초 | `screenshots/current/01-review-inbox.png` | 분석 전·진행 중·검수 가능 자료를 같은 목록에서 확인 |
| ②25초 | `screenshots/current/02-table-dto.png` | 원본 셀과 같은 행의 DTO·알레르기·검수 링크 |
| ③35초 | `screenshots/current/03-label-review.png` | 라벨 근거와 식품 정보 대조·수정·제외·승인 경계 |

기준 코드는 `402f0c7`이며 [현재 조회 기록](current-code-evidence.json)을 함께 사용합니다. 저장된 맘스케익 분석은 후보13개·원문 확인13구간·실제 모델 호출20회입니다. 후보에는 잘못 인식한 안내 문장도 있어 정확한 식품13개로 소개하지 않습니다. 촬영 당시 제외1개·대기12개이며 최종 승인은 수행하지 않았습니다. 현재 테스트는 Backend165/Frontend16 및 Vite 빌드 통과입니다. 백엔드 테스트는 격리 DB의 규칙 모드로 실행했습니다.

아래 준비 절차는 **선택적인 라이브 승인 시연**을 위한 별도 경로입니다. 아직 완료한 리허설로 표시하지 않습니다. 단순 조회는 현재 서비스의 자료·Agent 로그·검수·식품 DB 메뉴에서 할 수 있습니다.

## 시연 원칙

운영 자료와 회원 계정을 화면에 노출하지 않는다. 자료 비교·조회에는 사용자가 공유한 실제 기수집 자료를 사용할 수 있다. 승인·수정 저장 시연은 `demo/` 가상 입력과 별도 DB·assets에서 진행한다. 규칙 모드·테스트 대역·실제 LLM·저장된 캡처를 구분해서 설명한다. 준비 점검 성공은 실제 Agent와 DB 반영의 성공을 대신하지 않는다.

## 사전 준비

1. 발표할 브랜치·커밋을 기록하고 의존성·프런트 빌드를 준비한다. 새 환경은 루트 readmd.md의 설치 순서를 따른다.
2. 별도 시연 DB를 만들고 두 터미널에 동일한 환경을 설정한다. 아래 DB 이름이 기존 운영 DB와 다른지 확인한다. 이 안내는 기존 DB를 초기화하는 명령을 포함하지 않는다.

```sh
/opt/homebrew/opt/postgresql@17/bin/createdb -h 127.0.0.1 -p 55432 food_fms_demo
export DATABASE_URL=postgresql://localhost:55432/food_fms_demo
export FOOD_DATA_DIR="$PWD/.local/demo-assets"
export FOOD_ANALYSIS_MODE=agent
export FOOD_MODEL_URL=http://127.0.0.1:11434
export FOOD_MODEL_NAME=qwen3:8b
export FOOD_PLANNER_MODEL_NAME=qwen3:4b
export FOOD_EXTRACTION_MODEL_NAME=qwen3:8b
export FOOD_SEED_PASSWORD='직접_정한_시연용_비밀번호'
.venv/bin/python -m backend.app.seed
```

3. API는 8101에서 시작하고 worker는 같은 환경의 별도 터미널에서 실행한다. `.env.food`의 기존 값보다 위 환경변수가 우선한다. 새 터미널에는 위 export 값을 다시 설정한다.

```sh
# 터미널 1
.venv/bin/uvicorn backend.app.api.main:app --host 127.0.0.1 --port 8101
# 터미널 2: 같은 DATABASE_URL, FOOD_DATA_DIR, 모델 환경 사용
.venv/bin/python -m backend.app.domains.jobs.worker
```

4. `http://localhost:8101`을 시연 전용 브라우저 프로필에서 연다. 빌드한 프런트를 API가 직접 제공하므로 Vite의 8100 proxy는 사용하지 않는다. 다른 창의 운영 세션과 시연 세션을 혼동하지 않는다.
5. Ollama 서비스와 `qwen3:4b`·`qwen3:8b`를 준비한다. OCR을 시연하면 별도 Python 3.11 환경·모델 가중치·`FOOD_OCR_ENABLED`·`FOOD_OCR_PYTHON`도 설정한다. OCR을 준비하지 않았으면 텍스트/CSV 시연으로 범위를 밝힌다.
6. 사전 점검을 실행한다. 결과는 Git에 포함하지 않는 `.local/`에 둔다.

```sh
.venv/bin/python scripts/demo-preflight.py \
  --api-url http://127.0.0.1:8101 \
  --output .local/demo/preflight.json
```

이 점검은 API health, 모델 목록에 이름이 있는지, 프런트 빌드·핵심 패키지를 읽기만 한다. 추론·DB 연결/반영·실행 커밋 일치·OCR·Zoom은 검사하지 않으므로 결과에 각각 미검증으로 남긴다. 실패 종료코드 2는 준비 항목을 해결한 뒤 재점검하라는 뜻이다.

## 실제 모델 리허설

- [ ] 시연용 브랜치·커밋과 실행 폴더를 확인했다.
- [ ] API와 worker가 **같은 시연 DB와 assets**를 사용한다.
- [ ] admin 로그인이 되고 자료함·식품 목록·단가표가 열린다.
- [ ] `demo/notice.txt`를 등록하고 새 analyze 작업 ID를 기록했다.
- [ ] 실제 model_calls와 모델명·완료 상태를 확인했다. 테스트 대역/규칙 결과를 대신 쓰지 않았다.
- [ ] 원문 근거가 열리고 식품명·규격·알레르기·가격·날짜를 직접 대조했다. 추출 누락은 수정하거나 제외했다.
- [ ] 검토용 Excel을 열고 원문과 값·근거가 연결되는지 확인했다.
- [ ] 품목 확인만으로 식품 DB가 바뀌지 않는 것을 확인했다.
- [ ] 최종 승인·반영 작업이 성공하고 식품 상세의 단가·공급 상태·감사 이력이 원문과 연결된다.
- [ ] 잘못된 권한/미확인 필드/충돌 중 하나를 보여 줄 근거를 준비했다. 오류를 만들기 위해 운영 DB를 수정하지 않는다.
- [ ] `demo/prices.csv`의 공란과 0을 구분해 표시하는지 확인했다.
- [ ] 발표 시간 안에 처리하지 못할 수 있으므로 **성공한 실제 분석 결과**를 별도 준비했다.

공지 예제의 원문 단가는 “1봉당 16,500원”이다. 추출 값이 봉/총중량 기준 중 무엇을 뜻하는지 검토하고, 0원 CSV 행을 빈 값으로 바꾸지 않는지 확인한다. 예제를 정답이라고 기계적으로 승인하지 않는다.

## 선택: 별도 DB에서 85초 실시간 승인 시연

| 경과 | 행동 | 보여 줄 증거 |
|---|---|---|
| 0~10초 | 사전에 성공한 실제 모델 작업 열기 | 모델명·완료 상태·작업 ID |
| 10~35초 | 품목 선택, 원문/텍스트 전환, 값 수정 | 같은 DTO, 원문 근거, 공란·속성 분리 |
| 35~50초 | 사유 입력, 품목 확인 | 확인과 DB 반영의 구분 |
| 50~65초 | 최종 대상 승인·반영 | apply 작업 상태 |
| 65~85초 | 식품 상세와 변경 이력 | 변경 내용·적용일·근거 링크 |

중복 상품이나 적용 기간 충돌이 생기면 기존 식품 연결과 확인 사항을 보여 준다. 제약을 없애거나 실제 승인 이력을 지워서 시연을 맞추지 않는다. 리허설 후 자료를 그대로 쓰면 상태가 바뀌므로 라이브 시연은 새 가상 자료/검토 대상으로 준비한다.

## 장애와 대체 동선

| 상황 | 대응 |
|---|---|
| 실제 추론이 오래 걸림 | 진행 중인 상태를 짧게 설명하고 사전 성공 작업으로 전환 |
| 모델이 없거나 연결 실패 | 실제 실패를 표시하고 설치/실행 상태 확인. 규칙 모드를 실제 AI로 소개하지 않음 |
| 원문 이미지/로그인 접근 불가 | 준비한 가상 텍스트/CSV와 보관된 원문 사용. 계정 설정 화면을 공유하지 않음 |
| 승인 시 충돌 | 오류 사유와 원문/버전 검사 의미 설명. 준비한 성공 사례로 전환 |
| 전체 시연 환경 불가 | 실행 캡처와 CI를 보여 주고 실시간 시연을 완료했다고 주장하지 않음 |

## 현재 촬영과 과거 기록의 구분

현재 화면4장은 `screenshots/current/`에 보관했습니다. 2026-10-22 현재 서비스에서 읽기 전용으로 조회했으며 새 수집·추론·승인은 수행하지 않았습니다. 실행 중인 다른 작업 때문에 목록 상태는 이후 달라질 수 있습니다.

과거 코주부18행·planner1회·6.027초 실행은 `table-demo-result.json`과 기존 JPG 캡처에 남겨 둡니다. 현재 라벨 포함 분석의 속도나 호출 수로 인용하지 않습니다. Zoom·발표자 리허설은 별도로 확인합니다.
