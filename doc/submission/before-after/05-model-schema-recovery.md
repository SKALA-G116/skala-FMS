# 05. 한 라벨의 출력 형식 오류가 전체 분석을 중단한 문제

## 확인된 원인

2026-10-22 사용자 작업은15개 추출 묶음 중9개를 마친 뒤 `MODEL_SCHEMA_INVALID`로 실패했습니다. 원본 표13행과 기존 추출18품목은 저장돼 있었지만 완료 검수본을 만들지 못했습니다. 같은 보고서의 재시도도 같은 지점에서 중단됐습니다.

작업자 traceback과 저장 입력 재실행으로 검증한 직접 원인은 `events.maxItems=1`에 모델이2개 결과를 반환한 것입니다. 상품 하나의 포장 가격과 개당 가격을 각각 품목으로 출력했습니다.

생성용 JSON Schema는 큰 배열의 llama.cpp 문법 컴파일 비용을 피하려고 모든 maxItems를 제거하고 있었습니다. 이 때문에 단일 라벨용1개 제한도 제거됐습니다. 서버 검증은 정확하게 거절했지만 오류를 일반적인 형식 실패로 뭉뚱그렸고, 추출 단계에서는 이 오류를 구간별로 보류하지 않아 전체 작업이 실패했습니다. 마지막 실패 호출도 보고서에 저장되지 않았습니다.

## 범용 수정

| 수정 | 보장하는 경계 |
|---|---|
| 라벨 전용 schema | attributes_text·allergen_text·source_ids만 반환. 상품·규격·가격을 응답할 필드 자체를 제거 |
| 생성용 작은 배열 한도 유지 | maxItems4이하는 생성에도 유지. 큰 배열은 기존 성능 정책을 유지하되 원본 schema로 서버 검증 |
| 추출 오류 격리 | 형식·출력/입력 예산 오류는 원본 행 경계로 제한 분할. 분할할 수 없는 상품 영역은 원문 검수로 보존하고 다음 구간 진행 |
| 실패 호출·근거 보존 | extraction_failures에 구간·근거·처리 결과, model_calls에 validator·schema 경로·시간·토큰 기록 |
| 부분 완료 | 검수본·Excel 생성 후 해결 안 된 추출 구간은 partial로 표시. 확정 식품 DB에 자동 반영하지 않음 |
| 정직한 화면 상태 | 실패·취소를 처리 중으로 안내하지 않음. 일부 완료와 원문 검수 필요를 구분 |

원본 모델 응답이나 ValidationError의 원문 배열을 화면·로그에 덤프하지 않습니다. schema 경로·위반 종류·배열 개수 같은 제한된 진단만 남깁니다. source ID·필드 형식 검증을 끄거나 실패한 결과를 임의로 잘라내지 않습니다. 서버/모델 연결 장애는 성공으로 숨기지 않습니다.

## 실제 입력 재실행

실패 지점의 동일 OCR·표 입력을 사용했습니다. After는 라벨 목적에 맞게 prompt·응답 schema를 함께 축소했습니다. 두 번의 단일 실행이며 시스템 부하·예열을 통제한 반복 성능 실험은 아닙니다.

| 관찰 | Before 재현 | After 전용 응답 |
|---|---:|---:|
| 모델 | qwen3:8b | qwen3:8b |
| 응답 검증 | maxItems 위반, 결과2개 | 통과, 속성 원문·근거 객체1개 |
| 출력 토큰 | 1,091 | 397 |
| 호출 관찰 시간 | 59.41초 | 22.55초 |
| DB 승인 | 없음 | 없음 |

After의 원재료 원문372자·알레르기 원문13자와S1근거가 반환됐습니다. 이는 형식과 전달 경로 검증이며 실제 라벨의 모든 내용이 정확하다는 정답 평가가 아닙니다. 원본 입력·출력은 개인 자료를 포함해 `.local/schema-diagnosis/`에만 보관하고 Git에는 넣지 않습니다.

## 회귀 테스트

Backend159개·Frontend16개·Vite 빌드를 통과했습니다. 작은 배열 제한 유지·민감 출력 비노출·실패 호출 기록, 일반 텍스트의 schema 오류 행 분할, 라벨 schema/출력 제한 오류의 표 후보 보존·부분 완료·Excel·감사 근거, 중단 화면 안내를 검사합니다. 운영 작업은 기존 완료 지점부터 재개하며 사용자 승인과 별개입니다.

## 사용자 작업 재개 결과

저장된9개 완료 구간을 재사용하고 같은 분석의10~15구간을 처리했습니다. 재시도 작업 `e80253dc-a86a-491e-8cc2-aae7893096ad`는 succeeded, 전체15/15구간 완료, 보고서 completed와 검토 Excel 생성을 확인했습니다. 중복 통합 후13품목이 남았으며 재개 구간의 새 형식 실패 기록은0개입니다.

기존에 OCR·출력 예산으로 보류한70개 원문 구간은 수동 확인 대상으로 유지했습니다. 앞서 완료 처리한 구간을 모두 다시 추론하거나 이를 완전 자동 추출 성공으로 바꾸지 않았습니다. 확정 식품 DB 승인·반영은 수행하지 않았습니다.

[현재 검수 화면](http://127.0.0.1:8100/analysis-runs/b3c610d9-9e6f-4eb7-9188-9413ad60be6e/review)은 같은 로컬 DB·로그인이 있을 때 열립니다. 운영 데이터가 변경/삭제되면 링크가 유지된다고 보장하지 않습니다.
